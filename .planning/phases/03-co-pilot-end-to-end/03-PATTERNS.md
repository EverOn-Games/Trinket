## Pattern Assignments

### `data/repositories/activeSession.ts` (model/repository, CRUD single-key pointer)

**Analog:** `data/repositories/settings.ts` (single-blob accessor shape) + `data/repositories/sessions.ts` (JSON try/catch read pattern)

**Imports pattern** (`data/repositories/sessions.ts` lines 9-11):
```typescript
import { contentStorage } from '../mmkv';
import { newId } from '../../lib/id';
import type { Session } from '../types';
```
For `activeSession.ts`, drop the `newId` import (the pointer's `sessionId` is supplied by the caller, already generated by `sessionsRepo.create()`):
```typescript
import { contentStorage } from '../mmkv';
import type { ActiveSessionPointer } from '../types';
```

**Core pattern — single-key JSON blob with try/catch read** (`data/repositories/sessions.ts` lines 33-42, adapted to a single key instead of per-record + index):
```typescript
const KEY = 'activeSession:pointer';

function readPointer(): ActiveSessionPointer | undefined {
  const raw = contentStorage.getString(KEY);
  if (!raw) return undefined;
  try {
    return JSON.parse(raw) as ActiveSessionPointer;
  } catch {
    // Mirror sessionsRepo's readRecord tolerance (T-01-10): a malformed pointer
    // must not crash the app-boot reconciliation sweep.
    return undefined;
  }
}
```

**Repository object shape** — mirrors `settings.ts`'s flat `get()`/`update()` accessor shape (lines 10-32) rather than sessions.ts's index-based CRUD, since there is only ever 0 or 1 active session (RESEARCH.md Code Examples already gives the exact target shape — use it verbatim: `start(sessionId, startedAt, taskLabel?)`, `heartbeat(lastAliveAt)`, `read()`, `clear()`).

**Error handling pattern:** Every MMKV read goes through the try/catch-returns-undefined shape shown above — this is the established project-wide convention (`sessions.ts` lines 20-27 and 36-41, `dumpItems.ts` lines 17-23 and 32-36 both do this identically). Do not add a different error-handling shape for this repo.

### `data/types.ts` (+`ActiveSessionPointer`)

**Analog:** existing `Session`/`DumpItem` interfaces, same file (lines 16-22, 34-43)

**Pattern to copy** — plain exported interface, epoch-ms numeric fields commented `// epoch ms`, added directly below `Session`:
```typescript
// data/types.ts — addition, see RESEARCH.md Code Examples for the exact shape
export interface ActiveSessionPointer {
  sessionId: string;
  startedAt: number; // epoch ms — mirrors the linked Session's startedAt
  lastAliveAt: number; // epoch ms — heartbeat; liveness signal, NOT an aggregate
  taskLabel?: string; // denormalized for the D-11 resume card's copy
}
```

**CRITICAL — schema denylist compliance (Pitfall 1 from RESEARCH.md):** the field MUST be named `lastAliveAt`, not `lastActiveAt` — the denylist stem `lastactive` (see `data/repositories/__tests__/schema.denylist.test.ts` line 33) matches `lastActiveAt` as a case-insensitive substring and will fail `npm run verify`. `lastAliveAt` does not match that stem.

**Denylist test coverage note:** `schema.denylist.test.ts`'s *runtime probe* half (lines 62-90) only imports `sessionsRepo`/`dumpItemsRepo`/`intentionsRepo`/`useSettingsStore` — it will NOT automatically probe `activeSessionRepo`'s output unless that test file is extended to import and call it. The *source-scan* half (lines 92-99) DOES automatically cover `ActiveSessionPointer` since it scans `data/types.ts` verbatim for `name?:` patterns — this catches the new interface's fields with no test-file change needed. Recommend the plan explicitly add `activeSessionRepo.start(...)` to the runtime-probe's `allKeys` set too, for full parity with the other three schemas (belt-and-suspenders, not strictly required since the source-scan half already covers `lastAliveAt`/`taskLabel`/`sessionId`/`startedAt`).

### `src/features/co-pilot/reconcileActiveSession.ts` (utility, pure function)

**Analog:** `src/components/Mascot/useIdleScheduler.ts`'s `pickWeightedMicroBehavior` / `nextIdleIntervalMs` (lines 27-43) — pure, side-effect-free, independently unit-testable helper functions separated from the stateful hook that calls them

**Pattern to copy** — a pure function with an explicit signature (inputs in, discriminated-union result out, no MMKV/React import at all):
```typescript
// mirrors nextIdleIntervalMs's shape: pure inputs -> deterministic output, no I/O
export function nextIdleIntervalMs(
  reducedStimulus: boolean,
  random: () => number = Math.random
): number {
  const [min, max] = reducedStimulus ? [12000, 24000] : [4000, 9000];
  return min + random() * (max - min);
}
```
`reconcileActiveSession(pointer, now, thresholdMs) -> ReconcileAction` follows the identical shape: explicit inputs (no reading `Date.now()` or MMKV internally), explicit return, trivially testable with plain Jest `it()` blocks and no mocks. RESEARCH.md's Code Examples (lines 357-390) gives the exact target implementation.

## Shared Patterns

### MMKV read/write with try/catch JSON safety
**Source:** `data/repositories/sessions.ts` lines 33-42, `data/repositories/dumpItems.ts` lines 29-37
**Apply to:** `data/repositories/activeSession.ts` — every `JSON.parse` of a value read from `contentStorage` must be wrapped in try/catch returning `undefined` on failure. This is a load-bearing, project-wide convention (also cited in RESEARCH.md's Security Domain "Malformed/corrupted pointer JSON" threat entry).

### Screen shell + flattened styles
**Source:** `src/components/Screen.tsx`, `src/app/index.tsx` lines 69-85, `src/app/history.tsx` lines 46-49
**Apply to:** all `co-pilot.tsx` phases (setup/active/ending). Every screen renders inside `<Screen>`; every composed style is `StyleSheet.flatten([...])`, never a raw array — this is a hard expo-router `<Slot>` constraint, not a style preference (documented in `Screen.tsx` lines 23-26).

### Double-press guard via `useRef`
**Source:** `src/app/index.tsx` lines 57-63 (`isStartingSessionRef`)
**Apply to:** the setup screen's start affordances (one-liner submit, "Just work" tap, dump-item tap) and the active screen's End button — RESEARCH.md's Security Domain explicitly calls out reusing this exact guard shape for the End button and mood-check taps.

### AppState mocking via inline `jest.spyOn` (no dedicated `__mocks__/` file)
**Source:** `src/components/Mascot/__tests__/useReducedStimulus.test.ts` lines 19-23, 45-54
**Apply to:** `useElapsedSession.test.ts` and any other test touching `AppState`. Confirmed no `__mocks__/react-native` automock exists in this project (`jest.setup.ts` registers only 5 explicit mocks, none for RN core) — `AppState` is a plain JS-level export, spy it inline per-test, do not add a new `__mocks__/` file for it.

### Pure decision function + thin effectful wrapper
**Source:** `src/components/Mascot/useIdleScheduler.ts` (`pickWeightedMicroBehavior`/`nextIdleIntervalMs` vs. the `useIdleScheduler` hook itself)
**Apply to:** `reconcileActiveSession.ts` (pure) + `useReconcileActiveSession` in `_layout.tsx` (thin wrapper) — split logic from I/O so the decision is unit-testable with zero mocks, exactly as the Mascot module already does for its own timing/selection logic.

### i18n copy resolution in tests — always via imported locale JSON
**Source:** `src/app/__tests__/screens.test.tsx` line 17 (`import en from '../../../i18n/locales/en.json'`) and every `screen.getByText(en.<key>)` / `getByRole('button', { name: en.<key> })` call in that file
**Apply to:** every new integration test asserting on rendered copy — never hardcode an expected string; always resolve it from the imported `en.json` object, so a copy change never silently breaks tests without the diff being visible in the locale file itself.

### CLDR pluralized i18n keys for counted values
**Source:** `i18n/locales/en.json`'s existing `sessionsRemaining_one` / `sessionsRemaining_other` top-level keys
**Apply to:** `history.duration_{one,few,many,other}` (History row duration) and `coPilot.setup.lengthChip_{one,few,many,other}` (length-intent chip labels) — both explicitly named in UI-SPEC's Screen Contracts as reusing this exact CLDR-suffix convention; react-i18next resolves the suffix automatically from a `count` interpolation value, no manual pluralization logic needed.
