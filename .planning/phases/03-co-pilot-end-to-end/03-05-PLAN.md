<objective>
Close the UAT Test 4 gap (severity: major): the Co-pilot ending moment's skippable
3-level mood check auto-dismisses after ~1 second on real hardware and cannot be used.

Root cause (already diagnosed in 03-HUMAN-UAT.md ## Gaps): `EndingPhase` in
`src/app/co-pilot.tsx` wires the Mascot `acknowledge` one-shot's
`onStateAnimationComplete` → `handleAnimationComplete` → `finishEnding()` →
`router.replace('/')`. Navigation is therefore driven by the short (~1500ms
placeholder) acknowledge animation, so the user never gets a real chance to tap a mood.

**This plan REVISES locked decision D-13.** D-13's original "Pattern 3" treated the
acknowledge animation simply concluding as an *implicit skip that navigates Home*. On
real hardware that made the mood check unusable. The revised behavior: the ending screen
PERSISTS until the user makes an explicit choice (tap a mood OR tap Skip); the acknowledge
animation still plays but its completion does NOT navigate. Every other D-13/D-14 property
is preserved unchanged. Call this revision out explicitly in the code comment that replaces
the current "Pattern 3" comment so the decision-revision is traceable.

Also bundles the trivial, known fix for UAT Test 5 / review finding IN-02 (same file):
add `accessibilityState` to the SetupPhase one-liner Start Pressable so a screen reader
announces its disabled state.

Purpose: make the mood check actually usable (PILOT-05) and the Start CTA accessible.
Output: revised `EndingPhase` + `SetupPhase` in co-pilot.tsx, and updated/extended tests.
</objective>
