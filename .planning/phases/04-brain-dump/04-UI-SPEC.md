# Phase 4 — UI Design Contract: Brain Dump

> Visual and interaction contract for the Brain Dump capture view, grouped items list, item-row corrections (category/edit/delete), and the promote-to-Co-pilot hand-off (DUMP-01..05). Generated by gsd-ui-researcher, verified by gsd-ui-checker. This session ran **autonomously** (no interactive AskUserQuestion available) — every open visual/copy question was resolved with a recommended default and is explicitly flagged in **Flags** below for founder override.

**Locked upstream inputs used (not re-asked):** `04-CONTEXT.md` D-01..D-15 (text-core/voice-augment architecture, draft auto-restore, parsing, classification, chip correction, grouped list, delete/edit, promote), `04-RESEARCH.md` (expo-speech-recognition API, SectionList pattern, promote-hand-off mechanism, classifier pattern), `design/DESIGN-SYSTEM.md` (palette, dual-accent rule, constraint watch-items), `theme/tokens.ts` (landed dark tokens incl. `mascotGlow`), `.planning/phases/03-co-pilot-end-to-end/03-UI-SPEC.md` (reused verbatim: spacing scale, typography scale, color roles, no-icon-library precedent, promote target `beginSession`/`startFromDumpItem`), `.planning/phases/02-mascot-module/02-UI-SPEC.md` / `src/components/Mascot/types.ts` (locked 5-value `MascotState` union — no 6th "listening" state may be added, guarded by `noNegativeStates.test.ts`'s sibling state-count guarantee), `design/mockups/30a0b6e4-Brain_dump___listening.html` (voice-capture tone/layout reference), existing `i18n/locales/{en,pl}.json` (`brainDump.title`/`.description` keys already landed, `mascot.accessibility.*` keys reused verbatim).

## Spacing Scale

Trinket's actual landed scale (`theme/tokens.ts`) — 5 values, no `2xl`/`3xl` exist in this project, do not invent them:

| Token | Value | Usage this phase |
|-------|-------|-------|
| xs | 4px | Gap between a category chip's internal glyph/label padding; gap between the recording-status pill's dot and its text |
| sm | 8px | Gap between the five inline category-correction chip options; gap between an item row's Edit/Delete text links |
| md | 16px | Default padding inside cards/rows (item rows, the list screen's capture-affordance header card) — matches `Screen`'s existing content padding |
| lg | 24px | Vertical gap between the persistent capture-affordance header and the first category section; gap between the mascot and the prompt heading on the Capture view |
| xl | 32px | Gap above the Save button on the Capture view, separating it from the text field — mirrors Phase 3's "gap above the single End button" pattern |

Exceptions:
- The mic button, category-chip tap targets, and Edit/Delete text links must have a minimum 44×44 tap target (accessibility), achieved via internal padding or `hitSlop`, not a new spacing token — same exception Phase 3 already established.
- Mascot size presets remain the fixed pixel values locked in `02-UI-SPEC.md` (`md` 140×140 for `subtle`) — this phase does not introduce a new mascot size (see Flag 1: this screen uses `subtle`, not `prominent`).

*(Extends the base template — a multi-state capture + list flow needs per-screen copy/interaction detail beyond the base tables.)*

### 1. Capture view (`brain-dump.tsx`, `viewPhase: 'capture'`)

**Purpose:** Voice-forward *presentation*, text-core *architecture* (D-01). Rendered whenever the grouped list has zero items (D-12's empty-state routing) or when the user taps the list screen's persistent capture affordance.

**Layout (top to bottom):** kicker → mascot (`subtle`, see Flag 1) → prompt heading/subcopy → multiline text field (also the live-transcript surface, see Flag 2) → recording-status pill (conditional) → "or type instead" text link → mic button → Save button.

| Element | EN copy | PL copy (reference) | Notes |
|---|---|---|---|
| Kicker | "Brain dump" (reuse `brainDump.title`, rendered uppercase via style) | "Zrzut myśli" | Label role, letter-spaced; no new key needed |
| Prompt heading — idle (before first mic tap) | "What's on your mind?" (`brainDump.capture.prompt.idle`) | "Co masz w głowie?" | Heading role; shown until the mic is tapped |
| Prompt subcopy — idle | "Tap the mic, or start typing." (`brainDump.capture.prompt.idleSub`) | "Stuknij mikrofon albo zacznij pisać." | Body role, `textSecondary` |
| Prompt heading — recording | "I'm listening." (`brainDump.capture.prompt.listening`) | "Słucham." | Heading role — matches the mockup's exact tone |
| Prompt subcopy — recording | "Take your time." (`brainDump.capture.prompt.listeningSub`) | "Nie spiesz się." | Body role, `textSecondary` — matches the mockup verbatim |
| Text field placeholder | "Errands, calls, that thing about deposits, Friday's meeting… whatever's in your head." (`brainDump.capture.placeholder`) | "Sprawy, telefony, to coś o wpłacie, spotkanie w piątek… wszystko, co masz w głowie." | Multiline, no character limit, newline-separated (D-04/D-07) |
| "or type instead" link | "or type instead" (`brainDump.capture.textFallback`) | "albo napisz zamiast tego" | Plain `textSecondary` text link beneath the mic button; tapping focuses the text field directly — preserved verbatim from the mockup, a good accessibility/reliability precedent per `design/DESIGN-SYSTEM.md`'s own note |
| Recording-status pill | "Live · {{duration}} · recording" (`brainDump.capture.recordingLabel`, duration formatted `m:ss` via a formatter, not an i18n string) | same structure, "nagrywanie" for "recording" | Only rendered while actively recording; Label role, `surfaceElevated` pill background, tabular-nums for the duration digits |
| Mic accessibility label — idle | "Microphone — tap to speak" (`brainDump.capture.micLabel.idle`) | "Mikrofon — stuknij, aby mówić" | — |
| Mic accessibility label — active | "Listening — tap to stop" (`brainDump.capture.micLabel.active`) | "Słucham — stuknij, aby zatrzymać" | — |
| Voice-unavailable caption | "Voice isn't available right now — typing works great too." (`brainDump.capture.voiceUnavailable`) | "Głos teraz niedostępny — pisanie też świetnie działa." | Shown in place of the mic button whenever `isRecognitionAvailable()` is false, permission is denied, or a runtime STT error fires (see Flag 9: one shared caption for all three cases, not three different messages) |
| Save button | "Save these" (`brainDump.capture.save`) | "Zapisz wpisy" | Accent-filled pill, bottom of screen; disabled only in the sense that an empty field on tap is a silent no-op (D-07) — never a disabled/greyed visual state that could read as a rejection. (Specific verb+noun, not the banned bare "Save" — UI-checker Dimension 1.) |

**Interaction notes:**
- Mic permission is requested contextually on first mic tap only (D-03) — never upfront, never during any earlier screen.
- Recognized final utterances append as new lines directly into the same multiline text field the user can also type into (D-01/D-03) — there is no separate transcript-preview panel duplicating this text (see Flag 2, a deliberate departure from the mockup's separate-region layout, required by the text-core architecture).
- The draft (whatever is currently in the field, typed or dictated) auto-restores from a single MMKV key on screen mount and is cleared on Save (D-06) — this is silent; no "draft restored" banner or announcement.
- Tapping Save with a non-empty field: `parseDumpText()` splits into lines, `classify()` assigns a category to each, `dumpItemsRepo.create()` runs once per line, the draft key clears, and the screen transitions to the grouped list (`viewPhase: 'list'`).
- Tapping Save with only whitespace/blank content is a no-op (D-07) — no items created, no error shown, the field simply remains as-is (or the screen may stay put; no punitive feedback).

**No mascot on this screen** — mirrors `history.tsx`'s existing precedent of zero mascot presence on a utility/organizational list screen; the mascot's habitat this phase is the Capture view only (Flag 1).

### 3. Item row (rendered inside each section's `data`)

**Purpose:** Category correction (D-11), delete + inline text-edit (D-13), and the promote affordance (D-14/D-15) — each inline, no modals, no separate screens.

**Layout:** Line 1 — category chip (tappable) + trailing quiet marker if promoted. Line 2 — item text (Body, wraps up to 3 lines). Line 3 (footer) — "Edit" / "Delete" text links, flex-spacer, "Start a session" accent button.

| Element | EN copy | PL copy (reference) | Notes |
|---|---|---|---|
| Category chip (collapsed) | current category's label (reuse `brainDump.category.*`) | reuse | `surfaceElevated` background, `textSecondary` label — deliberately NOT accent-colored in its collapsed/passive state (see Flag 7); tapping expands the 5-option picker |
| Category chip options (expanded) | all 5 category labels, compact row | reuse | The currently-selected option is accent-filled (mirrors Phase 3's length-intent-chip precedent); the other 4 are `surfaceElevated`/`textSecondary`. Tapping any option sets the category and collapses back to Line 1 |

| Promote button | "Start a session" (`brainDump.item.promote`) | "Zacznij sesję" | Accent-filled pill; routes to `/co-pilot` with `dumpItemId` (D-14, RESEARCH.md Pattern 6) — no duplicated session-creation logic in this file |
| Promoted quiet marker | "· in Co-pilot" (`brainDump.item.promotedMarker`) | "· w Co-pilot" | Label role, `textSecondary`, trailing on Line 1 whenever `item.promotedTaskId` is set; item text also renders slightly dimmed (`textSecondary` instead of `textPrimary`) — never a badge, count, or "completed" treatment (D-15). **Interaction notes:**
- Only one of {category-picker-expanded, edit-mode, delete-confirm} is active per row at a time; opening one collapses any other open state on that same row.
- Promoting never removes, hides, or reorders the item (D-15) — it stays exactly where it was in its category section.

## Flags (non-blocking — recommended defaults, confirm only if founder has a strong opinion)

1. **Mascot state mapping and prominence are a discretionary translation of the mockup's "ears-forward listening" cue.** `MascotState` is locked to exactly 5 values (`greeting`/`idle`/`presence`/`dozing`/`acknowledge` — no 6th "listening" state may be added, mechanically guarded by `noNegativeStates.test.ts`'s sibling union-count assertion). This spec maps: `idle` before the mic is tapped, `presence` while actively recording, back to `idle` when recording stops. Prominence is hardcoded `subtle` (140×140, mirrors Co-pilot's own precedent of hardcoding prominence per-screen rather than reading user settings) since the text field/mic are this screen's primary interactive surface, not the mascot. The mascot does **not** appear at all on the grouped list screen (mirrors `history.tsx`'s existing zero-mascot precedent for utility/list screens). Confirm if a different state/prominence mapping is preferred.
2. **Live transcript renders directly inside the single multiline text field, not a separate preview region as the literal mockup shows.** This is required by D-01/D-03's text-core architecture ("transcript lands live in the field"), not a stylistic choice — flagged because it's a visible layout deviation from the mockup file, even though it's the correct reading of the locked decision.
3. **Mic glyph is a Unicode emoji ("🎤"), not a custom icon or new icon-library dependency** — matches the Phase 3 mood-check precedent (plain emoji for a small, fixed glyph set) rather than adding `react-native-svg`-based custom icons or a package like `@expo/vector-icons`. Swappable for a custom asset later with zero architecture change. Confirm if a different visual is preferred.
4. **No destructive/danger color token exists in `theme/tokens.ts`.** Per Phase 2's D-08 precedent ("don't invent new tokens unless a concrete need exists"), this phase does not add one. The "Delete this?" inline confirmation uses neutral typography (`textPrimary`, semibold) rather than a red/warning treatment. Flag for founder review if a distinct danger token is wanted — this is the first phase with a genuinely destructive (permanent data loss) action, so it's a reasonable point to revisit the single-accent-plus-mascot-glow palette.
5. **The recording-active mic button gets a soft `mascotGlow` (amber) ring, in addition to its `accent` (terracotta) fill.** This is a deliberate, thematically-consistent extension of the dual-accent rule (terracotta = action, amber = mascot/ambient presence) — read as "the mascot is listening too," not a new semantic color. Confirm if this feels like scope creep versus a plain accent-only treatment.
6. **Polish category labels are draft translations pending native-speaker review**, same flag `04-RESEARCH.md` already raised for the classifier's own PL/EN keyword lists (Assumptions Log A1). "Do załatwienia" (errands) in particular is a phrase choice among several plausible options ("Sprawunki" being the main alternative) — confirm before shipping.
7. **Category chips are deliberately NOT accent-colored in their collapsed/default state** — only the actively-selected option inside an expanded 5-option picker gets accent fill (mirroring Phase 3's length-intent-chip precedent). This keeps accent scarce/meaningful per the dual-accent rule and reinforces D-11/§4.2's "suggestion, not a verdict" framing — a bright accent-colored category label by default could read as a completed/authoritative tag rather than a light suggestion.
8. **Custom font loading (Fraunces/Inter/JetBrains Mono) — RECOMMEND DEFERRING again this phase**, extending Phase 2/3's Flag 1. `System` + `fontVariant: ['tabular-nums']` continues to approximate the mockup's monospace duration digits.
9. **STT-unavailable and permission-denied states share ONE caption** (`brainDump.capture.voiceUnavailable`) rather than two separate messages. This is intentional: distinguishing "the system doesn't support this" from "you said no" would risk the second reading as an implicit rebuke ("you denied us something"), which cuts against the shame-free/PDA-aware constraint. Confirm if the founder wants the two cases distinguishable to the user (e.g. for support/troubleshooting reasons) — Pitfall 1's Jest test coverage (per `04-RESEARCH.md`) still exercises both cases distinctly at the code level regardless of shared copy.
