## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] package.json name field leaked from scaffold temp directory**
- **Found during:** Task 1 (scaffold + install)
- **Issue:** `create-expo-app` used the temp directory name `trinket-scaffold` as the generated `package.json`'s `name` field
- **Fix:** Edited `package.json` `name` to `"trinket"`
- **Files modified:** `package.json`
- **Verification:** `node -e "console.log(require('./package.json').name)"` → `trinket`
- **Committed in:** `a066744` (Task 1 commit)

**2. [Rule 3 - Blocking] Missing expo-env.d.ts caused `tsc --noEmit` to fail**
- **Found during:** Task 2 (post-prebuild verification)
- **Issue:** `npx tsc --noEmit` failed with `Cannot find module './animated-icon.module.css'` and `Cannot find module or type declarations for side-effect import of '@/global.css'` — these resolve via ambient declarations normally shipped in an auto-generated `expo-env.d.ts` (`/// <reference types="expo/types" />`), which is only written by `expo start`'s type-generation step and had never run in this headless sandbox
- **Fix:** Wrote `expo-env.d.ts` by hand using the exact template string extracted from `node_modules/expo/node_modules/@expo/cli/build/src/start/server/type-generation/expo-env.js` (`/// <reference types="expo/types" />` plus the standard do-not-edit comment) — not hand-rolled logic, byte-identical to what the Expo CLI itself would generate
- **Files modified:** `expo-env.d.ts` (gitignored per scaffold default, not committed — this matches Expo's own convention of never committing this file)
- **Verification:** `npx tsc --noEmit` now exits clean with zero errors
- **Committed in:** Not committed (gitignored generated file, consistent with upstream Expo convention)

## Issues Encountered

- The live `default@sdk-56` template generates routes under `src/app/` (with a `@/*` TypeScript path alias) rather than a bare top-level `app/` directory assumed by the plan's `files_modified` list and RESEARCH.md's illustrative project-structure sketch. This is not a bug — it's simply what the current `expo-template-default@56.0.27` package produces — and was accommodated by committing the actual generated paths. Later plans referencing `app/_layout.tsx` etc. should use `src/app/_layout.tsx` instead.
- No `babel.config.js` or `metro.config.js` was generated by this template version (both are handled by Expo's implicit default config in current SDK 56 tooling) — not added since nothing in the project yet requires customizing either; flagged here so a later plan doesn't assume they exist.
- Per Open Question 1 in RESEARCH.md: `expo prebuild --clean` succeeded fully for config generation on this Linux sandbox (both `ios/` and `android/` folders produced with `app.json` values correctly applied). CocoaPods (`pod install`) was auto-skipped by the Expo CLI itself with the message "Skipped installing CocoaPods because operating system is not on macOS" — this is expected, non-blocking behavior, not a failure. Actual native compilation (`expo run:ios`/`run:android`, real device boot) remains unverifiable in this sandbox and is deferred to the user's own hardware or an EAS cloud build, per Environment Availability in RESEARCH.md and this plan's `<verification>` section.
